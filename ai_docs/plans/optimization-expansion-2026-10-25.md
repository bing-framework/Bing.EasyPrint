## 三、解决方案与接口安排

### 第一阶段：Host、预览与 CI

**O1：升级 DesignerHost**

- Host 和 Host 测试项目一起升级到 `net10.0`，同步验证脚本、启动说明及当前操作命令。
- 核心库、模板库继续保留五框架；历史验收文档中的运行时和结果不改写。
- 使用 .NET 10 当前稳定修补版本；不顺带升级 ImageSharp 或其他核心依赖。

**O2：一次渲染生成预览包**

- 新增 `/api/designer/preview-bundle` 和对应协商特性，返回 ZIP：布局清单、当前页可支持元素的 PNG、逐元素诊断。
- 每个请求只调用一次模板渲染，复用该次布局及 primitive ownership 生成图片；切换页面时请求对应页。
- 前端保留现有去抖、取消和旧请求失效机制；旧 Host 回退既有预览链路。
- 不引入跨请求共享缓存。图片、ZIP、元数据及临时缓冲区纳入现有预算；取消、资源超限或整体渲染失败不得返回不完整压缩包。
- 不支持的软件像素能力继续显示明确原因；普通元素图片失败不抹掉有效布局。

**O3：跨平台验证**

- 新增 GitHub Actions Windows/Linux 工作流，运行 .NET 10 Host、前端构建、Vitest、Chromium E2E 及核心库的现代运行时消费验证。
- 核心测试项目增加 `net10.0` 验证目标，不改变生产库五框架。
- 固定字体用例使用仓库夹具；系统字体用例单独安装、确认所需常规、粗体和中文字库后运行。
- Windows 保留真实 `net6.0`、`netcoreapp3.1` 验证。Linux 不通过运行时滚动冒充旧框架通过。
- 保存命令、实际运行时、测试数量及 TRX；外部 CI 尚未运行时记录证据缺口。

### 第二阶段：完整新协议注册

**O4：建立协议中立的注册与渲染入口**

- 新增字符串协议标识、注册表、协议中立能力描述、后端工厂及模板布局适配契约。
- 新后端接收统一 `PrintDocument`，输出有序 `PrintPageOutput`；声明 DPI、支持元素、字体/条码度量、限制及软件预览能力。
- 模板布局适配器负责目标相关的测量、元素转换和分页策略。新协议不得借用虚假的内置枚举值，也不得隐式套用 CPCL/TSPL 度量。
- 任务进纸、裁切和独立控制文件通过可选收尾接口表达，包含预检、输出长度及插入位置；未声明能力时提前拒绝。
- 旧 `IPrintProtocolProvider`、工厂、渲染入口和结果类型保持原契约，通过适配接入共同执行逻辑；新入口使用独立的协议标识及结果类型。
- Provider 按渲染会话创建，会话负责释放；注册表启动后冻结。重复标识、未知协议和无效配置明确拒绝。

**Host 与设计器接入**

- 新增协议目录接口及 `protocol-registry` 特性；请求增加可选 `protocolId`、协议配置对象，与旧协议选择方式互斥。
- 注册描述包含名称、配置字段、约束、默认值及能力；设计器根据声明生成配置表单。
- 协议配置限 JSON 数据，服务端验证为准。注册采用宿主启动代码和显式程序集引用，不接受请求上传可执行插件。
- 项目文件升级到 DesignerProject v2，保存新目标和编辑器状态；继续读取 v1 与裸模板。未知协议保留配置并禁止渲染，不自动替换成内置协议。
- 提供独立程序集中的示例协议，证明不修改核心枚举、内置分发或前端协议列表即可完成注册、布局、预览和输出。示例不宣称真实设备兼容。

### 第三阶段：格式化与批量生成

**F1：可持久化字段格式化**

- 为 `BgField` 增加可选格式配置，支持数字/金额、日期时间、枚举映射、补零、前后缀和空值文本。
- 固定处理顺序：取值 → 空值处理 → 类型转换/映射 → 格式化 → 补齐 → 前后缀。
- 缺省配置完全保留现有行为；缺失字段路径仍报错，空值默认只处理实际 `null`。
- 默认使用 InvariantCulture；需要地区格式时显式配置文化。日期接受明确格式或 ISO 输入，不使用运行机器的当前区域、当前时间或隐式时区转换。
- 数字使用十进制语义；格式化失败携带元素和字段路径，不静默输出原始值。
- 不执行脚本或任意表达式。`ValueFunc` 保持仅内存模板可用。
- Host 返回权威显示值，前端不另写一套数值格式化逻辑；新增特性协商和 JSON 往返测试。

**F2：批量数据入口与结果包**

- 支持 UTF-8 CSV、JSON 对象数组、JSONL；第一版不增加 Excel 依赖。
- CSV 默认保留字符串和前导零，通过显式字段映射及格式配置转换类型；支持引号、分隔符、换行和 BOM，拒绝重复列名及无效结构。
- 提供记录选择、逐条预览、份数字段、进度、取消和失败筛选。
- 新增批量渲染接口，客户端分块提交，每块最多 25 条，服务端顺序处理。接口也可供业务程序直接调用，不建立持久化队列。
- 默认整批最多 1000 条、实际输出最多 1000 页、累计结果上限 32 MiB；单条继续遵守现有资源限制。达到上限明确停止，不自动提高预算。
- 输入、绑定、编码错误按记录汇总；内部异常、取消和整批资源超限终止任务。取消后不自动下载尚未完成的结果。
- 结果 ZIP 使用稳定记录序号目录，保留页面、份数及 segment 顺序，附 `manifest.json` 和 `errors.csv`。不得把独立控制文件拼成单文件。
- 部分成功显示“部分完成”；全部失败只提供错误报告，不显示生成成功。错误表包含原始记录序号、字段/元素路径和错误码，并处理 CSV 公式转义。

### 第四阶段：Digital Link 与 AI 编辑器

**F3：GTIN Digital Link**

- 新增独立构建、解析和规范化 API，按 [GS1 Digital Link URI Syntax 1.7.0](https://ref.gs1.org/standards/digital-link/uri-syntax/1.7.0/) 实现未压缩 URI。
- 第一版主标识限定 AI `01`；限定符顺序和合法分支读取固定字典的 `dlpkey` 元数据，包括 `22/10/21` 与合法替代分支。其他主标识明确拒绝。
- 处理 GTIN 校验、查询属性、百分号转义、重复 AI、非法限定符组合和往返一致性；保留非 GS1 查询参数，不能静默丢失。
- 构建时显式提供 HTTPS 基址；解析不联网、不访问 resolver。压缩 URI、解析服务部署和在线产品信息不纳入第一版。
- 新增可选结构化 GS1 输入，AI 项支持静态值或字段路径；与旧单字符串来源互斥。
- Digital Link 输出进入普通 QR/DataMatrix 路径，与 FNC1 的 `Gs1=true` 模式互斥；PDF417 和 Composite 不接受 Digital Link 输入。
- 逐字段及 URI 结构始终校验；完整 `req/ex` 沿用显式关联校验设置。

**F4：可视化 AI 编辑**

- 从核心固定字典公开只读元数据，并由 Host 提供版本化目录；前端不复制维护另一份 AI 字典。
- 提供 AI 搜索、说明、长度/字符约束、静态值或字段绑定、排序及删除。
- 结构化编辑、括号元素串和支持的 Digital Link 输入可以转换；转换失败保留原输入并定位具体 AI。
- 增加结构化诊断，包含 AI、错误类别、关联或冲突项；保留已有抛异常入口的兼容语义。
- 使用真实 Host 校验已绑定数据。动态值未提供时显示“待数据验证”，不提前声明合法。

### 第五阶段：导出与设计器操作

**F5：位图 PDF 与码图 SVG**

- PDF 只开放给明确支持准确整页光栅的目标，首个内置目标为 ESC/POS Raster；页面尺寸按 `dots × 72 / DPI` 转为 PDF point。
- 页面使用原始单色输出，不经截图、不重新排版；多页顺序、页面尺寸及份数与当前输出一致。
- PDF 依赖放在 Host，不引入核心五框架。采用已核对 MIT 许可的 PDFsharp Core `6.2.4` 固定版本；升级另行处理。
- SVG 从共享编码器的模块矩阵/条纹生成矢量矩形，不把 PNG 嵌入 SVG 冒充矢量。
- 覆盖可软件编码的一维码、QR、DataMatrix、PDF417、Composite；保留静区、旋转、尺寸和物理单位。
- 第一版 SVG 为“码图 SVG”，不包含设备 HRI/可读文字；界面明确标注。未支持码制拒绝导出。
- PDF/SVG 增加能力协商、独立下载入口，并纳入批量结果生成及资源预算。

**F6：锁定、排列和数据撤销**

- 锁定防止移动、缩放、删除及属性修改；父节点锁定对子节点有效，允许从结构树解锁。
- 锁状态存于项目 v2 的编辑器元数据，使用稳定节点标识；复制、移动、编组、拆组和删除同步维护映射，不污染打印模板。
- 增加左/中/右、上/中/下对齐及水平/垂直均分。第一版只操作同一容器内的绝对定位元素；流式节点明确禁用。
- 排列使用旋转后的实际占位框；均分至少三个元素，以两端元素固定计算间距，整数舍入不得造成累计漂移。
- 编辑历史加入业务数据与编辑器状态；一次排列、映射或导入对应一次撤销操作。原始无效 JSON 文本也可撤销。
- 保留现有 80 次历史上限；大批量数据采用有总字节预算的不可变快照，避免每次操作复制完整数据集。
