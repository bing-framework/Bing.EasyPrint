# 第二阶段 O4：架构与验收安排

日期：2026-10-25。来源：用户批准的总计划；本文件具体化实现边界，不缩减完整协议注册范围。前置 O1/O2/O3 本地实现已收口，外部 CI 证据单列。

## 分层决策

1. 核心新增协议标识、冻结注册表、协议中立能力与后端会话契约。核心不依赖模板、Host 或前端；新协议标识不映射为虚假 PrintProtocol 枚举。保留旧公开接口签名，内置协议经适配进入共同执行路径。
2. 模板层新增目标布局适配契约，沿用现有绑定、模板图、条件/重复、布局轨迹和资源管理逻辑。适配器真正决定测量、元素转换、分页约束；不能仅包装旧 Render 并借用 CPCL/TSPL 度量，也不能另写仅支持样例的简化模板解释器冒充完整接入。
3. 后端会话按请求/渲染创建和释放。配置为 JSON 数据快照；冻结注册表与描述不应因调用方修改集合而改变。预检、取消、异常、预算超限均不返回部分输出。独立控制文件沿用 PrintPageOutput 的边界与顺序。
4. 任务收尾通过可选契约声明预检、长度和插入位置；未声明能力早拒绝。旧路径原有份数、feed/cut 默认值和输出字节保持；新协议不继承 ESC/POS 默认切纸行为。
5. Host 启动代码显式注册可信程序集后冻结。目录接口与 protocol-registry 协商供设计器发现名称、配置字段、约束和能力。HTTP 新旧选择器互斥要按请求字段是否实际存在判断，不能让旧 DTO 的默认 Cpcl 把 protocolId 请求误判，亦不能静默忽略显式冲突字段。
6. 设计器从目录生成新协议选项/配置表单，项目 v2 保存目标与编辑器元数据，读取 v1 和裸模板。未知协议或旧 Host 不支持注册特性时保留配置、禁止对应渲染与下载，不能回退替换为内置协议。F6 的锁定/排列功能留第五阶段，v2 先建立稳定的状态容器。
7. 示例协议在独立程序集；Host 只增加明确引用和启动注册。新增另一个注册协议不得要求改核心枚举、内置 switch 或前端协议列表。示例声明自己支持的范围，其他能力明确拒绝，不冒充真实设备。

## 必要验收

- 内置适配前后字节、页数、份数及 segments 顺序一致；保留公共 API，新增 API 中文 XML 完整。
- 重复 ID、冻结后修改、未知 ID、错误配置及新旧字段冲突明确失败；描述/配置快照不受外部可变对象影响。
- 独立示例从核心 PrintDocument 到模板再到真实 Host/浏览器完成接入。改变示例自定义字宽或分页约束，实际断行/坐标/页数必须相应改变，不只改变目录说明。
- 结合现有模板能力验证绑定、重复/条件与布局归属的复用。可支持元素的预览包仍只渲染一次，不支持的软件像素有原因。
- 有收尾与无收尾后端分别证明预检、长度、插入顺序、独立控制文件、取消和 Dispose；失败后再次请求不受污染。
- 真实浏览器发现样例、编辑生成的配置、预览、导出、保存/重载 v2；v1/裸模板兼容；未知协议保留/禁用；旧 Host 降级。

## 影响与证据

影响范围：核心公开增量抽象、模板布局与渲染会话、Host 路由/协商、设计器项目格式/配置/预览/下载，以及独立示例程序集。风险 HIGH；生产五 TFM 不变，Host net10 不变。不得覆盖既有 API 基线。

先定向契约/回归，再受影响完整测试；本阶段跨共享渲染与公共 API，收口须重跑五框架严格 XML、核心 net10/net6/netcoreapp3.1、Host、前端 build/Vitest、完整 Chromium（workers=1/retries=0）、模板案例及候选包消费。字体与外部环境证据边界继续保留。无相关热点改动不重跑性能探针。

代码与测试由同一 OpenCode / deepseek-v4.1-flash 会话实施；主代理维护计划和架构复核。证据写 `artifacts/optimization-expansion-20261025/phase2/` 唯一运行目录，报告 `docs/optimization-expansion-phase2-2026-10-25.md`。阶段最多三轮集成修正；完成 O4 后交主代理验收，不提前混入 F1—F6。
