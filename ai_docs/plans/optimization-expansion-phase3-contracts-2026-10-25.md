# 第三阶段 F1/F2：契约与验收安排

依据已批准的总计划实施字段格式化与批量生成。OpenCode / deepseek-v4.1-flash 负责代码/测试/使用文档；主代理负责契约、独立复核和阶段放行。仅 F1/F2，不提前实现 Digital Link、AI 编辑器、PDF/SVG 或 F6 操作历史。核心/Templates 五框架、现有公共签名和缺省行为保持；不提交、推送、发布、改产品版本或旧 API 基线。

## F1：格式化必须进入真实绑定路径

- 在 `BgField` 增加可 JSON 持久化的可选格式配置，接入 `Binding.Text` 的既有解析链；保留原始标量直到转换完成，不能先 ToString 或经过 JS Number 丢失 decimal 精度。无配置走原行为。
- 固定顺序：取值→实际 null 处理→类型转换/映射→格式化→补齐→前后缀。缺失路径仍是绑定错误，空字符串不能默认视为 null。null 替代文本不再尝试数字/日期转换，但按已定义的补齐和前后缀步骤处理，明确写入契约。
- 数字/金额使用 decimal 和显式格式；默认 InvariantCulture，文化仅显式配置。日期支持明确输入格式或明确 ISO 形式，保留时区/offset 语义，不调用当前时间、系统当前文化或隐式本地时区转换。提供负数补零、舍入及金额表示的明确示例。
- 枚举映射未命中、无效文化/格式、数字溢出、无效日期都明确失败并保留元素路径和字段路径；不要输出原值掩盖错误。配置只能是数据，不执行表达式或脚本；ValueFunc 仍仅内存模板可用。
- 长格式、补齐长度和输出计入既有预算，不能依靠构造巨大字符串后再检查。重用既有绑定/资源诊断，不另造吞异常路径。
- Host 返回权威显示值，前端通过真实预览显示；前端只编辑配置，不复制金额/日期算法。格式化配置需要新增特性协商；旧 Host 保留配置并明确说明无法渲染，不能静默打印未格式化的值。
- 设计器配置编辑、项目 v1/v2/裸模板读取、JSON 保存往返和 C# 案例齐备。不得遗漏 Composite 主/次数据等共用 BgField 的现有入口。

## F2：无持久队列的有界批量流程

- 输入：UTF-8 CSV、JSON 对象数组、JSONL。CSV 默认字符串、保留前导零；字段映射后由服务端格式化配置转换类型。支持 BOM、引号转义、分隔符、字段内换行；重复列、错列/畸形结构明确报错。拒绝顶层标量/数组条目等非独立记录；原始记录序号在筛选和失败重试显示中保持稳定。
- UI：导入和字段映射、记录选择、逐条真实预览、份数字段、进度、取消和失败筛选。默认导出成功记录及错误清单；部分完成和全部失败的状态分开。取消不自动下载未完成结果。
- HTTP 新增协商特性和批量接口，每块最多 25 条、块内顺序处理，允许业务程序直接调用。复用单条请求的协议解析、预检、模板渲染和有序输出逻辑，包括 O4 注册协议。
- 一次用户批次最多 1000 条、实际物理输出最多 1000 页、累计结果不超过 32 MiB。保留每条现有预算。客户端提交下一块前检查累计量；服务端限制单请求并验证请求的剩余页/字节预算不超过全局上限。不能把 32 MiB 当作每块额度后让最终结果无限累加。
- 不建立跨请求共享可变状态、后台任务或持久队列来模拟整批。明确文档：单 HTTP 块的服务端保证和客户端整批的累计保证；若向业务调用方提供剩余额度/偏移参数，校验其范围并返回明确消耗统计。独立调用方按相同契约聚合。
- 页数必须按实际副本计算，不能仅数逻辑页/ZIP 文件。复制次数和原有 job/copies 的组合必须明确定义或明确拒绝冲突，不能悄悄相乘或忽略。复用已经验证的 source/copy/segment/finishing 顺序和边界。
- 输入/绑定/编码错误按记录汇总，包含稳定记录序号、字段/元素路径、错误码；内部异常、取消和整批资源超限终止批次，不归类成可继续的一条错误。达到限制明确停止，不能提高额度或输出截断文件。
- ZIP 使用稳定记录目录，保留每页/副本/命令 segment/独立收尾，附 manifest.json、errors.csv。全失败只返回错误报告，不标生成成功。errors.csv 对不可信文本做公式转义，并正确引用逗号、双引号和换行。
- 累计原始输出、最终 ZIP、清单、错误表和临时合并缓冲均计入相应现有资源预算；不得把独立控制文件拼成单文件。F5 尚未实施，当前只导出已有协议输出，不添加假 PDF/SVG 选项。

## 实施与测试次序

1. F1 模型、格式化/绑定、中文 XML、JSON 契约、定向测试；再接 Host/设计器编辑、降级与实际案例。
2. F2 输入解析及记录模型、共享批量执行/输出、预算与取消；再接 UI、真实 Host 浏览器及可运行业务调用案例。
3. 阶段候选一次完整受影响验收，独立复核后放行。执行中发现本阶段具体可执行缺陷先修复，不通过扩大后续功能范围替代。

定向必须覆盖：

- 数字/金额/日期/映射/补零/前后缀/null 的正常及错误路径；在不同 CurrentCulture/时区下结果稳定；decimal 精度、缺失路径、重复行/组件路径；无配置旧字节不变、JSON 往返一致。
- CSV 前导零、嵌入换行/引号/BOM、重复列、JSON/JSONL 非法结构；映射错误不丢记录序号。
- 1/25/26/1000 记录边界，超过 1000 拒绝；可使用轻量计数后端验证大边界，至少小批次真实编码。25/26 验证实际分块而非直接调用单块接口。
- 混合成功失败、全失败、跨块累计页/字节上限、多页多份、独立收尾与 segment 顺序、取消和内部异常。先证明任何失败均无损坏/不完整 ZIP，再验证 UI 状态与下载。
- 真实 Host：配置格式→显示值→保存重载；CSV/JSONL 导入→选择记录→逐条预览→多块输出→检查 manifest/错误表/协议字节；旧 Host 降级，不 mock 代替成功链路。

阶段门禁按实际变更影响：Core/Templates 五框架严格 XML；真实 net10/net6/netcoreapp3.1 核心测试；Host 默认脚本；前端类型/生产构建/Vitest/Chromium（workers=1、retries=0）；模板 C#/JSON/往返案例与当前候选现代/net6 包消费。保留首次失败、实际框架、通过/失败/跳过数、命令及退出码。使用独立 `artifacts/optimization-expansion-20261025/phase3/`，不覆盖前两阶段证据。

第三阶段从初版实施开始，集成修正最多三轮；两轮同问题无进展停止。外部 CI 独立 BLOCKED_EXTERNAL，不重复本地全量测试补偿。只针对 OPEN_ACTIONABLE 修正；阶段报告应区分已实现、已验证、尚未实施及外部证据缺口。
